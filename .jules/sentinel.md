## 2025-02-13 - [Prevent XSS in Comparator UI Stream List]
**Vulnerability:** XSS vulnerability in `comparator_ui.js` and `comparator_integrated.js` where user-controlled variables (`s.label`, `s.count`, `sym`) were being directly concatenated and inserted into the DOM via `innerHTML` without prior sanitization. This allowed execution of malicious scripts if external documents or localStorage contained injected payloads.
**Learning:** `innerHTML` concatenations are susceptible to XSS if not properly escaped, specifically because parsed docx files/localStorage configurations can be manipulated.
**Prevention:** Explicitly use an `escapeHtml()` function to escape essential characters (`&`, `<`, `>`, `"`) before injecting dynamically generated text content into `innerHTML` statements.
## 2025-02-14 - [Prevent XSS in Apps Script Admin Panel]
**Vulnerability:** XSS vulnerability in `apps-script-export-sanitized/Index.html` where customer data (like `customer_id`, `name`, `email`) and dynamic error messages were being concatenated into an HTML string and injected into the DOM via `innerHTML` without sanitization. Inline JavaScript handlers (`onclick="addPointsAction('...')"`) were also vulnerable to breakouts.
**Learning:** Even internal or admin panels relying on Google Apps Script (GAS) must sanitize variables injected into `innerHTML`. Inline JS handlers require both HTML and JavaScript escaping to prevent XSS breakout (e.g. escaping single quotes).
**Prevention:** Use an `escapeHtml()` function for direct DOM injection, and prefer passing data via `data-*` attributes (`data-id="..." onclick="addPointsAction(this.dataset.id)"`) to avoid complex JS quote escaping in inline handlers.
