## 2025-02-13 - [Prevent XSS in Comparator UI Stream List]
**Vulnerability:** XSS vulnerability in `comparator_ui.js` and `comparator_integrated.js` where user-controlled variables (`s.label`, `s.count`, `sym`) were being directly concatenated and inserted into the DOM via `innerHTML` without prior sanitization. This allowed execution of malicious scripts if external documents or localStorage contained injected payloads.
**Learning:** `innerHTML` concatenations are susceptible to XSS if not properly escaped, specifically because parsed docx files/localStorage configurations can be manipulated.
**Prevention:** Explicitly use an `escapeHtml()` function to escape essential characters (`&`, `<`, `>`, `"`) before injecting dynamically generated text content into `innerHTML` statements.
## 2025-02-13 - [Sanitize innerHTML injection in Apps Script Client]
**Vulnerability:** DOM-based Cross-Site Scripting (XSS) vulnerability inside `apps-script-export-sanitized/Index.html` where data sourced from Google Apps Script APIs (like user details, error messages, etc.) was unsafely injected into the page via string concatenation into `innerHTML` properties and `onclick` JavaScript event attributes.
**Learning:** `innerHTML` and inline `onclick` string interpolation are fundamentally unsafe when dealing with external API data. A malicious payload fetched via the server response could escape the intended HTML or JS string constraints.
**Prevention:** Implement and apply a standalone `escapeHtml` function before writing text to `innerHTML`, and use `escapeJsQuote` alongside `escapeHtml` specifically to secure inline string variables passed directly into inline JavaScript attributes (`onclick`).
