## 2025-02-13 - [Prevent XSS in Comparator UI Stream List]
**Vulnerability:** XSS vulnerability in `comparator_ui.js` and `comparator_integrated.js` where user-controlled variables (`s.label`, `s.count`, `sym`) were being directly concatenated and inserted into the DOM via `innerHTML` without prior sanitization. This allowed execution of malicious scripts if external documents or localStorage contained injected payloads.
**Learning:** `innerHTML` concatenations are susceptible to XSS if not properly escaped, specifically because parsed docx files/localStorage configurations can be manipulated.
**Prevention:** Explicitly use an `escapeHtml()` function to escape essential characters (`&`, `<`, `>`, `"`) before injecting dynamically generated text content into `innerHTML` statements.
## 2026-06-11 - [Dual Escaping for Inline JS Event Handlers]
**Vulnerability:** XSS vulnerabilities in `apps-script-export-sanitized/Index.html` where dynamically generated variables (like `customer_id` and `status`) were concatenated directly into inline JavaScript event handlers (e.g. `onclick="..."`) and injected into the DOM via `innerHTML`.
**Learning:** When injecting variables into inline JavaScript event handlers within dynamically generated HTML via `innerHTML`, standard HTML escaping is insufficient because browsers decode HTML entities before executing the JavaScript. This can allow attackers to break out of string quotes and execute malicious JS.
**Prevention:** Use a context-aware JS escaping function (like escaping single and double quotes) alongside HTML escaping (e.g., `escapeHtml(escapeJsQuote(val))`) when inserting dynamic content into inline JS event handler attributes.
