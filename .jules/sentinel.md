## 2025-02-13 - [Prevent XSS in Comparator UI Stream List]
**Vulnerability:** XSS vulnerability in `comparator_ui.js` and `comparator_integrated.js` where user-controlled variables (`s.label`, `s.count`, `sym`) were being directly concatenated and inserted into the DOM via `innerHTML` without prior sanitization. This allowed execution of malicious scripts if external documents or localStorage contained injected payloads.
**Learning:** `innerHTML` concatenations are susceptible to XSS if not properly escaped, specifically because parsed docx files/localStorage configurations can be manipulated.
**Prevention:** Explicitly use an `escapeHtml()` function to escape essential characters (`&`, `<`, `>`, `"`) before injecting dynamically generated text content into `innerHTML` statements.
## 2026-06-24 - Prevent XSS in Apps Script UI innerHTML injections
**Vulnerability:** User-controlled fields (`name`, `email`, etc) were concatenated unescaped into HTML strings and injected via `innerHTML` in the admin dashboard (e.g., `apps-script-export-sanitized/Index.html`), leading to a DOM-based Cross-Site Scripting (XSS) vulnerability. Inline JavaScript handlers (`onclick`) also concatenated these variables unescaped, leading to XSS attribute breakouts.
**Learning:** Legacy UI files lacking a framework or standard templating often use raw `innerHTML` for dynamic rendering. Both HTML contexts and Javascript attribute contexts require their own specific escaping mechanisms because browsers decode HTML entities in attributes before executing JavaScript. Standard HTML escaping is insufficient for variables injected into `onclick` attributes.
**Prevention:** Always implement and use a context-appropriate escaping function like `escapeHtml` for DOM nodes, and additionally a JS quote escaping utility (e.g., `escapeJsQuote`) for variables injected into inline Javascript strings. Example: `<button onclick="action('${escapeHtml(escapeJsQuote(val))}')">`.
