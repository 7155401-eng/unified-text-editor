## 2025-02-13 - [Prevent XSS in Comparator UI Stream List]
**Vulnerability:** XSS vulnerability in `comparator_ui.js` and `comparator_integrated.js` where user-controlled variables (`s.label`, `s.count`, `sym`) were being directly concatenated and inserted into the DOM via `innerHTML` without prior sanitization. This allowed execution of malicious scripts if external documents or localStorage contained injected payloads.
**Learning:** `innerHTML` concatenations are susceptible to XSS if not properly escaped, specifically because parsed docx files/localStorage configurations can be manipulated.
**Prevention:** Explicitly use an `escapeHtml()` function to escape essential characters (`&`, `<`, `>`, `"`) before injecting dynamically generated text content into `innerHTML` statements.
## 2025-02-14 - [Prevent XSS in Admin Dashboard]
**Vulnerability:** XSS vulnerabilities in `apps-script-export-sanitized/Index.html` where user-controlled inputs (like `c.customer_id`, `c.name`, `c.email`, `c.status`) and external error messages were concatenated directly into `innerHTML` statements. In addition, user data was incorrectly concatenated into inline JavaScript (`onclick="addPointsAction('` + c.customer_id + `')"`).
**Learning:** Standard `escapeHtml` does not protect against XSS if the data is injected directly into an inline JavaScript string literal context, because HTML entities are decoded by the parser before JavaScript execution. Furthermore, a naive `escapeHtml` truthy check (`if (!str)`) incorrectly swallows falsy valid numeric values like `0`.
**Prevention:** Implement `escapeHtml` checking strictly for `null` (`if (str == null)`), use `data-*` attributes read via `this.dataset` for dynamic variables tied to inline JS event handlers, and strictly use `escapeHtml` before appending variables to HTML content.
