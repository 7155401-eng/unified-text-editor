## 2025-02-13 - [Prevent XSS in Comparator UI Stream List]
**Vulnerability:** XSS vulnerability in `comparator_ui.js` and `comparator_integrated.js` where user-controlled variables (`s.label`, `s.count`, `sym`) were being directly concatenated and inserted into the DOM via `innerHTML` without prior sanitization. This allowed execution of malicious scripts if external documents or localStorage contained injected payloads.
**Learning:** `innerHTML` concatenations are susceptible to XSS if not properly escaped, specifically because parsed docx files/localStorage configurations can be manipulated.
**Prevention:** Explicitly use an `escapeHtml()` function to escape essential characters (`&`, `<`, `>`, `"`) before injecting dynamically generated text content into `innerHTML` statements.

## 2025-02-13 - [Prevent XSS in GAS Admin Dashboard]
**Vulnerability:** XSS vulnerability in Google Apps Script export (`apps-script-export-sanitized/Index.html`) where user-controlled variables (customer details like name and email, and server error messages) were concatenated directly into the DOM via `innerHTML` without prior sanitization. In addition, variables were injected into inline javascript attributes (`onclick="..."`), allowing breakout via quotes.
**Learning:** `innerHTML` concatenations are susceptible to XSS even in exported or admin tools if they render user-supplied data (such as user names and emails). Also, simply HTML-escaping strings is insufficient when injecting variables into inline JS event handlers; a secondary JS string-quote escape is required before the HTML escape.
**Prevention:** Implement and explicitly use `escapeHtml()` when interpolating any dynamic user data or error messages into `.innerHTML` assignments. Further, implement and use a context-aware `escapeJsQuote()` function to wrap arguments destined for inline JS attributes (e.g., `escapeHtml(escapeJsQuote(val))`).
