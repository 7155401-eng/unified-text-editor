## 2025-02-13 - [Prevent XSS in Comparator UI Stream List]
**Vulnerability:** XSS vulnerability in `comparator_ui.js` and `comparator_integrated.js` where user-controlled variables (`s.label`, `s.count`, `sym`) were being directly concatenated and inserted into the DOM via `innerHTML` without prior sanitization. This allowed execution of malicious scripts if external documents or localStorage contained injected payloads.
**Learning:** `innerHTML` concatenations are susceptible to XSS if not properly escaped, specifically because parsed docx files/localStorage configurations can be manipulated.
**Prevention:** Explicitly use an `escapeHtml()` function to escape essential characters (`&`, `<`, `>`, `"`) before injecting dynamically generated text content into `innerHTML` statements.
## 2025-05-18 - [XSS vulnerability in apps-script-export-sanitized/Index.html via `innerHTML`]
**Vulnerability:** XSS vulnerability in `apps-script-export-sanitized/Index.html` where customer data properties (like `c.name`, `c.email`, etc) and `err.message` strings were directly concatenated and set to `innerHTML`. This allowed executing arbitrary Javascript if data returned from the backend contained `<script>` tags or malicious payload. Furthermore, values such as `c.customer_id` and `c.status` were placed inside inline JS event handlers (e.g., `onclick="addPointsAction('" + c.customer_id + "')"`) inside `innerHTML`. Without proper JS escaping, single quotes from the payload could break the event string and execute Javascript.
**Learning:** Standard HTML escaping (`escapeHtml()`) is not enough for strings injected dynamically into inline Javascript within `innerHTML`. A payload like `\',alert(1)//` would bypass HTML escaping because the entity is parsed by the browser prior to Javascript execution. Backslashes and quotes must be securely escaped via an `escapeJsQuote` function.
**Prevention:** Implement and apply `escapeHtml` for all dynamically inserted text within `innerHTML` block generation. Where a value must be passed inside an inline JS handler string within `innerHTML`, wrap the value with `escapeHtml(escapeJsQuote(value))` to first safely escape Javascript syntax (quotes and backslashes) before applying HTML entity replacement.
