## 2026-05-13 - [style_registry.js Cache Optimization]
**Learning:** The style registry was repeatedly calling synchronous I/O (`localStorage.getItem`) and expensive parsing (`JSON.parse`) on every element style application, creating a severe bottleneck during dense page renders. Memory caching for static/rarely-changing global configurations is highly effective, but cross-tab synchronization must be handled manually via the `storage` event to prevent stale states in multi-window environments.
**Action:** When implementing global configuration managers, always use an in-memory cache variable backed by `localStorage` rather than querying `localStorage` continuously. Ensure cache invalidation logic is robust (both local updates and cross-tab `storage` events).

## 2024-05-19 - [Cache LocalStorage Strings and Parsed Objects for Layout Configurations]
**Learning:** Frequent reads of `localStorage.getItem` coupled with `JSON.parse` during performance-critical layout and rendering loops (`dom_packer.js` and `vilna_v9_apply.js` queries to `noMidLineSplits`, etc.) result in severe Garbage Collection (GC) pressure and main-thread synchronous I/O blocking.
**Action:** Always implement an in-memory cache for high-frequency configuration modules (e.g., `spacing_settings.js` and `document_style_settings.js`) that caches *both* the raw JSON string (to quickly detect non-mutations without parsing) and the parsed settings object. Synchronize caches with a cross-tab `storage` event listener, and use the cached provider functions in layout loops instead of raw `localStorage` reads.
