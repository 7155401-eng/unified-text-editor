## 2026-05-13 - [style_registry.js Cache Optimization]
**Learning:** The style registry was repeatedly calling synchronous I/O (`localStorage.getItem`) and expensive parsing (`JSON.parse`) on every element style application, creating a severe bottleneck during dense page renders. Memory caching for static/rarely-changing global configurations is highly effective, but cross-tab synchronization must be handled manually via the `storage` event to prevent stale states in multi-window environments.
**Action:** When implementing global configuration managers, always use an in-memory cache variable backed by `localStorage` rather than querying `localStorage` continuously. Ensure cache invalidation logic is robust (both local updates and cross-tab `storage` events).

## 2026-06-24 - [Layout Settings Configuration Cache Optimization]
**Learning:** `loadSpacingSettings` and `loadDocumentStyleSettings` were frequently reading and parsing values from `localStorage`, causing synchronous I/O bottlenecks in rendering loops. Repeated `JSON.parse` operations also create unnecessary Garbage Collection pressure. The application settings can dynamically change across tabs or be reset entirely.
**Action:** Implemented an in-memory cache for layout configurations backed by `localStorage`. Wrapped cache invalidation `storage` event listeners with `typeof window !== "undefined"` to ensure SSR compatibility, and checked for both `e.key === STORAGE_KEY` and `e.key === null` to correctly handle `localStorage.clear()` events without stale configurations. Ensured shallow copies were returned to prevent consumers from mutating the global cache unintentionally.
