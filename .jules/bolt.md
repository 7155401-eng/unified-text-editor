## 2026-05-13 - [style_registry.js Cache Optimization]
**Learning:** The style registry was repeatedly calling synchronous I/O (`localStorage.getItem`) and expensive parsing (`JSON.parse`) on every element style application, creating a severe bottleneck during dense page renders. Memory caching for static/rarely-changing global configurations is highly effective, but cross-tab synchronization must be handled manually via the `storage` event to prevent stale states in multi-window environments.
**Action:** When implementing global configuration managers, always use an in-memory cache variable backed by `localStorage` rather than querying `localStorage` continuously. Ensure cache invalidation logic is robust (both local updates and cross-tab `storage` events).
## 2025-02-14 - [Layout Configuration Parsing Overhead]
**Learning:** Functions like `loadSpacingSettings` and `loadDocumentStyleSettings` were parsing configuration values from `localStorage` on every invocation. Since these are frequently accessed during the tight loops of layout measurement and DOM packing, the repetitive synchronous I/O and `JSON.parse` created a measurable performance bottleneck. Memory caching was effective here but required careful implementation with `storage` event listeners for cross-tab synchronization and explicitly shallow cloning returned values (e.g. `return { ...cachedSpacingSettings }`) to prevent shared state mutation bugs without invoking the deep-clone overhead of `JSON.parse(JSON.stringify)`.
**Action:** Always identify and memory-cache redundant `localStorage.getItem` and `JSON.parse` calls in hot paths (like rendering or layout loops). Ensure caches are isolated via shallow cloning and are correctly synchronized via `storage` events.
