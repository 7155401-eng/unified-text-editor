## 2026-05-13 - [style_registry.js Cache Optimization]
**Learning:** The style registry was repeatedly calling synchronous I/O (`localStorage.getItem`) and expensive parsing (`JSON.parse`) on every element style application, creating a severe bottleneck during dense page renders. Memory caching for static/rarely-changing global configurations is highly effective, but cross-tab synchronization must be handled manually via the `storage` event to prevent stale states in multi-window environments.
**Action:** When implementing global configuration managers, always use an in-memory cache variable backed by `localStorage` rather than querying `localStorage` continuously. Ensure cache invalidation logic is robust (both local updates and cross-tab `storage` events).

## 2023-10-24 - [Cache Spacing Settings in loadSpacingSettings]
**Learning:** `loadSpacingSettings` in `src/spacing_settings.js` parses `localStorage.getItem("ravtext.spacing.v1")` with `JSON.parse` every time it is called. Functions checking `localStorage` individually like `noMidLineSplitsEnabled` and `noMidParagraphSoftEnabled` in `src/engine/dom_packer.js` and `readSpacingBool` in `src/vilna_v9_apply.js` were also parsing this value independently. This is extremely slow and causes severe synchronous I/O bottlenecks in tight loops.
**Action:** Implement memory cache for `loadSpacingSettings` to avoid `JSON.parse` penalty on subsequent reads. Also, refactor `noMidLineSplitsEnabled` and `noMidParagraphSoftEnabled` in `src/engine/dom_packer.js`, and `readSpacingBool` in `src/vilna_v9_apply.js` to rely on the cached `loadSpacingSettings`.
