## 2026-05-13 - [style_registry.js Cache Optimization]
**Learning:** The style registry was repeatedly calling synchronous I/O (`localStorage.getItem`) and expensive parsing (`JSON.parse`) on every element style application, creating a severe bottleneck during dense page renders. Memory caching for static/rarely-changing global configurations is highly effective, but cross-tab synchronization must be handled manually via the `storage` event to prevent stale states in multi-window environments.
**Action:** When implementing global configuration managers, always use an in-memory cache variable backed by `localStorage` rather than querying `localStorage` continuously. Ensure cache invalidation logic is robust (both local updates and cross-tab `storage` events).

## 2023-10-25 - localStorage Polling and Parsing Optimization
**Learning:** In layout rendering loops, checking configuration by parsing `localStorage` every time (e.g. `JSON.parse(localStorage.getItem(key))`) creates severe Garbage Collection (GC) pressure. However, completely removing `localStorage.getItem` requires listening to cross-tab `storage` events, which doesn't capture intra-tab updates easily without emitting custom events.
**Action:** When caching `localStorage` data for high-frequency functions (like layout loops), cache BOTH the raw string and the parsed object. Comparing the raw string from `localStorage.getItem` (which is fast) with the cached raw string avoids the expensive `JSON.parse` call and object allocation when the data hasn't changed, while maintaining correct state dynamically.
