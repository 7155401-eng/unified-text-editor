# V9 — שילוב מילת הפתיח בתכנון הפסקה

## מצב והיקף

העבודה מבוססת על `82936b7ba1720714f6ae73bda95e9791f6873856`, בענף `fix/v9-unified-opening-layout`. היא מיועדת לבדיקת קבלה לפני מיזוג ל־main. אין במסמך זה אישור שכל מסמך אמיתי או כל גופן כבר נבדקו.

התיקון שאושר למיקום הטקסט הראשי נשמר: `const mainStrips = rawMainStrips;`. אין החזרה של חיתוך שטח הראשי באמצעות `carveStripsAroundBoxes`. לא נעשו שינויים בתפריט העליון, בחשבונות, בתלויות או בקובצי גופנים.

## חוזה האחריות החדש

V9 קובע את השורות ואת מיקום הפתיח לפני סגירת העמוד. הצייר מקבל החלטה סופית; הוא אינו מאחד שתי שורות, אינו משתמש ב־float כדי לשבור אותן מחדש, ואינו מקטין פתיח או משנה את מספר השורות בשלב הציור.

המודולים החדשים הם חלק ממסלול V9, לא מנוע תיקון שרץ אחריו:

| מודול | אחריות |
| --- | --- |
| `src/engine/v9_source_fragments.js` | טקסט קנוני, מיפוי UTF-16 למקור, חיתוך פסקאות תוך שמירת עיצוב ועוגנים |
| `src/engine/v9_main_inline_layout.js` | תכנון משותף לפתיח ולטקסט; שורות, גאומטריה, שבירות והמשך לעמוד הבא |
| `src/engine/v9_text_measurement.js` | מדידה וציור המשתמשים באותם מקטעים מעוצבים; ניהול גופנים ומטמון |

`vilna_v9.js` קורא למודולים כחלק מתכנון העמוד. המודל הישן נשאר בקבצים לצורך תאימות, אך אינו הסמכות הפעילה של הטקסט הראשי במסלול החדש.

## שימור מקור וגבולות

כל שורה סופית כוללת זהות פסקה וטווח במקור. `sourceText` הוא הטקסט שנצרך מאותה פסקה. הוא כולל מפרידים ושבירות; חיבור הטווחים לפי סדרם מאפשר לבדוק שאין דילוג או כפילות.

הבדיקה מתייחסת לטקסט הקנוני של V9, לאחר עיבוד הסימונים בכניסה, ולא לבייטים של קובץ Word. מיפוי נפרד שומר קשר למיקומי הטקסט הגולמי. אין הבטחה לשחזור בינארי של קובץ המקור.

שארית עמוד נשמרת כמקטעי פסקאות, ולא כמחרוזת אחת המאחדת סוף פסקה ותחילת פסקה אחרת. המשך אמיתי אינו מקבל פתיח נוסף. פסקה מקורית חדשה שומרת את זהותה והגדרותיה. הפניות בגבולות מקטעים משויכות פעם אחת, כולל הפניה בסוף פסקה המורכבת רק ממילת פתיח.

## גאומטריה וציור

רצועות העמוד אינן משתנות בגלל תוצאות הציור. רוחב שורה נגזר מהתחום המוקצה לכל גובה השורה; מעבר לרצועה רחבה אינו מאפשר לשורה לחצות שטח שלא הוקצה לה.

פתיח נפתח שומר את המידות המבוקשות, וגובה ההקצאה הוא לפחות גובה האות בפועל ולפחות מספר השורות המבוקש. פתיח מוגבה משתתף בשבירת השורה כמקטע מעוצב רגיל. המרווח אחרי הפתיח נובע מאותה יחידת גודל במדידה ובציור; אין מקדם חצי נסתר או רזרבת 8% של הטור במסלול החדש.

כאשר פתיח אינו נכנס לשטח, המערכת מחזירה שארית או שגיאת פריסה מפורשת; היא אינה מקטינה בשקט ואינה מוחקת מקור. שורה או פסקה שאינן נכנסות אינן נצרכות בכוח. תקרת עמודים מחזירה `complete: false` ואת החומר שנותר. אלה עדיין מצבים המחייבים בדיקת התנהגות בממשק לפני שחרור.

תוכניות השורות ננעלות לאחר יצירתן. רכיבי ציור מסומנים ב־`data-v9-layout-final`, ומעבדי המטא־נתונים והמתיחה הישנים מדלגים על השורות שבבעלות המתכנן החדש.

## עיצוב וגופנים

נתוני runs והפניות אינם נמחקים בהפרדת הפתיח מגוף הפסקה. המדידה משתמשת בסגנון האפקטיבי, כולל המרת pt ל־px וגופן שירש המקטע. מטמון המדידה מוגבל למחזור העבודה ומבוטל כאשר דור הגופנים משתנה. המתנה לטעינת גופנים שנכשלה בזמן אינה מדווחת כמוכנות מוצלחת.

גופן חסר עדיין עשוי לגרום לדפדפן לבחור חלופה. המתנה ל־FontFaceSet אינה הוכחה שהגופן המסחרי של המשתמש מותקן. בדיקות Chromium נעשות בגופנים הזמינים בסביבת CI; נדרשת בדיקה נוספת בסביבת המשתמש עם הגופן המקורי.

## בדיקות קיימות

37 בדיקות יחידה בקבצים `tests/v9-unified/*.test.mjs`. אחת מהן כוללת 50 רצפי פגינציה שונים. הכיסוי כולל מיפוי מקור, ניקוד ו־UTF-16, חיתוך עיצוב, הפניות גבול, מעבר בין רצועות, שבירות מפורשות, פתיחים של 1–8 שורות, פסקאות המשך ותוכניות שאינן משתנות בציור.

27 תרחישי Chromium, באמצעות `scripts/v9-unified/run-browser.mjs`: פתיח נפתח ומוגבה בשלוש משפחות גופנים; מידות DOM מול התוכנית; ציור חוזר; עיצוב נקודתי; מקור רב־עמודים; זרמי צד עם מספור מופעל ומכובה; פסקה ארוכה המתפצלת לעמודים; תקרת עמודים; timeout גופנים; מניעת שינוי מאוחר על ידי מעבדים ישנים; ביטול לפני תחילת ציור.

בתרחיש הארוך שנבדק נוצרו 13 עמודים ו־121 שורות. זהו תרחיש בדיקה סינתטי, לא המסמך המקורי בן מאות העמודים. זמניו אינם תחזית לביצועי המסמך המקורי.

## בדיקת שרשרת הבנייה

ה־workflow `.github/workflows/v9-unified-opening.yml` מריץ בדיקות יחידה ודפדפן, בונה את הבסיס המקורי ואת הענף עם אותו package-lock, משווה שינויים בקובצי המקור, ואז מריץ שוב את בדיקות היחידה והדפדפן על המקורות שלאחר הבנייה.

סקריפטי הבנייה הישנים משכתבים קבצים מסוימים גם ללא שינוי זה. `verify-build-sources.mjs` אינו מתעלם מהם: כל שכתוב שנותר חייב להיות בקובץ שאינו שונה מהבסיס לפני הבנייה, ולהפיק תוצאה זהה לבסיס לאחר הבנייה. שכתוב חדש או שכתוב בקובץ שעבר את המיזוג מכשיל את הבדיקה. ביטול שכתוב שהיה קיים בבסיס מותר ומתועד.

## שחזור בדיקות בסביבת פיתוח מבודדת

```sh
npm ci --ignore-scripts
node --test tests/v9-unified/*.test.mjs
npx --no-install playwright install chromium
node scripts/v9-unified/run-browser.mjs
npm run postinstall
npm run build
node --test tests/v9-unified/*.test.mjs
node scripts/v9-unified/run-browser.mjs
```

יש להריץ בעותק בדיקות נפרד, משום שסקריפטי הבנייה הקיימים עשויים לשנות קבצים. ה־CI שומר דוחות `unit.tap`, `browser.json`, `browser-before-build.json`, לוגי בנייה ודוח השוואת מקור. תוצאות CI מתייחסות למזהה הקומיט הרשום בכל ריצה.

## שער קבלה לפני מיזוג

נדרשת בדיקה במסמך המקורי, עם הגופן וההגדרות המקוריים, ובפרט: מיקום הטקסט הראשי בין זרמי הצד, פתיחים על גבולות עמוד ורוחב, עיצוב והפניות, פסקאות קצרות, הדפסה וייצוא, עריכה ובנייה מחדש, וביצועים בהיקף המלא. לא בוצעה כאן בדיקת קצה־לקצה מלאה של ייבוא Word, כל פעולות הממשק או ייצוא PDF.

צילום HTML קיים אינו תחליף למקור: מידע שכבר אבד לפני הצילום אינו ניתן לאימות נגד המקור מתוך הצילום בלבד. אין לצרף למאגר הציבורי את מסמך המשתמש או את קובצי הגופן לצורך בדיקה.

אין למזג או להפעיל פרסום אוטומטי על סמך מספר בדיקות בלבד. נקודת השחזור נשארת `82936b7`; השינוי נבחן בענף נפרד עד בדיקת הקבלה.
